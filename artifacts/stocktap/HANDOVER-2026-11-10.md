## What was built

### 1. Bottles and cans counted as full cases + loose (`src/lib/packaged.ts`, `src/components/PackagedEntry.tsx`)
- Lines counted `each` (J2O, Red Bull, mixers, bottled beer, cans, crisps). First count asks once
  "How do these come in?": suggested size (24 up to 460ml, 12 for 500–600ml, none for snacks),
  any of 6/8/10/12/15/18/20/24/30/36, a typed size, or "one by one" (`pack_size = 1`).
- `pack_size` on an `each` line = case size. **Valuation is unchanged**: cost_price stays per single
  unit. The old `dozen` method treats cost_price as per case, which is why lines were NOT switched
  to `dozen` (that would have multiplied stock values).
- Saved entry: `part_value` = total single units, `full_containers` = cases (reference only).
  Everything downstream (stock-display, stocktake-close, till, reports) reads `part_value` for
  `each`, so nothing else changed.
- `computeCategoryReading` `each` case returns through `finishReading` directly. The shared
  ending adds `fullContainers × capacity` again, which would have double counted cases.
- Case size saves offline (localStorage queue, same pattern as hiding a line) and flushes on the
  next products fetch. Library edit form shows "Case size (1 = singles only)" on `each` lines.
- Display everywhere: `79 bottles · 6 doz 7 · 3 cases + 7`.

### 2. Days left + what to order on every line (`src/lib/line-forecast.ts`, `src/hooks/useLineForecasts.ts`)
- Stock now = newest real count (readings, server first, Dexie offline) + deliveries since − sales
  since at the line's speed (never below 0 before a delivery; reuses `stockNow` from stock-orders).
- Sales speed: own counts ≥7 days apart (prev + deliveries between − latest) → stock audits (same
  basis/busy/cover settings as the Orders page, read from localStorage `orders:*`) → own counts
  3–6 days apart → none ("No sales speed yet", no order figure. Never guess).
- Order rounded up to what the line comes in: case of N, keg/cask, box, bottle.
- Library: label + detail per line, "To order (N)" filter sorted soonest-out first. Removed the old
  `Nd cover` / `Order now` badges (`calcCoverage` ignored deliveries).
- Library "In stock" now merges server reading history with the Dexie map (a fresh phone used to
  show deliveries only).

### 3. Orders page fixes (`src/lib/stock-orders.ts`, `src/pages/orders.tsx`)
- `orderList(..., { startFor })`: a line counted in StockTap after the latest audit starts from that
  count, not the audit's closing count. Teal Farm's latest audit is 25 Sept; it was estimating 46
  days of sales on top. Page says "N lines start from your newer StockTap count instead."
- `packFor`: `each` lines with a case size order in cases (was single units; disagreed with Library).

### 4. Today's check (`src/lib/check-picks.ts`, Spot Check pick screen)
- One button ticks up to 10 lines: running low (out / <7 days, soonest first), dearest lines not
  checked for 7+ days (stock value at cost, top 5), never checked (priced, by cost). Each shows its
  reason; suggested lines listed first. Anything can be added/removed by hand.
